# Bundle contract

v39 updates Laser Sentry Cooldown to v1.1: an overheated sentry no longer explodes (its overheat ability is set to none) and, once cooled, its turret powers up again through the AI's own pending state request; a check every 120 frames reads 1 to 3 values while no sentry cools and allocates nothing. It is still a plaintext entry from its own `scripts/build.py` `assemble()` (lock field `entry: direct`), and its bundled suites now include `tests/test_turret.lua`, run in LuaJIT and in the game's `lua51.dll`. The other twenty components are unchanged from v38.

v38 adds four options: Hellpod Drop Hold v1.2, Laser Sentry Cooldown v1.0, Match Your Colors v1.2 and Sticky Grenade Handles v1.0. Laser Sentry Cooldown, Match Your Colors and Sticky Grenade Handles are plaintext entries from their own `scripts/build.py` `assemble()`, like Flame Damage Fixed (lock field `entry: direct`); Match Your Colors also carries its English texts, so `components` is now a translation kit of seven mods. Hellpod Drop Hold ships two resources: its plaintext entry, which requires `mods/cowboybingus/hellpod_drop_hold_impl`, and that compiled implementation, both built by its own `scripts/module.py`. Its option archive carries both, the lock pins the second in `extra_resources`, and the build and package checks require both to match the standalone v1.2 release byte for byte. The other seventeen components are unchanged from v37. The option-selection suites replay 720 of the 2,097,152 selections.

v37 updates all seventeen components to their 2026-10-04 releases: each mod now uses Bingus Shared Runtime v1 (update guard, memory access, checked writes), keeps the game data it located instead of locating it again every frame, and decodes fields from bytes; Know Your Constellation and Better Lobby Management carry a Simplified Chinese translation (`locales/zh-Hans.lua`). Every resource still equals its standalone release byte for byte. With a loader older than v18 the pack now raises the machine-code limit to 64 MB.

v36 updates six components and drops the Rows package (Know Your Constellation v4 has a single layout): Know Your Constellation v4.0, Better Lobby Management v1.1, Mod Options Menu v1.1, Mod Bindings Menu v2.1, Ship Station Hotkeys v1.8 and Shallow Water Diving v3.9. Each now carries the shared text module `src/bingus_text.lua` and its English texts `locales/en.lua`, which its own builder embeds: Mod Options Menu, Mod Bindings Menu and Ship Station Hotkeys became entries assembled by their `scripts/entry.py`, like Better Lobby Management (lock field `entry: direct`; the build runs the component's builder on the vendored sources), Shallow Water Diving is compiled by its own `scripts/module.py`, and Know Your Constellation's `scripts/module.py` wrapper no longer has a Rows variant. The build requires each resource to match its standalone release byte for byte. The other eleven components and Mod Bindings Menu's input actions are unchanged from v35. `tests/test_components.py` checks that `components` is a translation kit of the six (TRANSLATING.md).

Unreleased v37 (study candidate, not published) takes every component from its resilience-v1 source. `scripts/build.py` assembles each option with the component's own recipe: `scripts/entry.py` for Better Lobby Management, Mod Options Menu, Mod Bindings Menu, Ship Station Hotkeys, Clickable Scrollbars and Arc Thrower Revamped; Flame Damage Fixed's `scripts/build.py` `assemble()`; `scripts/module.py` `build_module` for Better Stratagem Bounce, Hellpod Steering Unlocked, Reinforcement Beacons Fixed, Consistent Vaulting, Shallow Water Diving, Sentry Aim Retention and Enemy Collision Synchronized; the `scripts/module.py` wrapper for Armory Preview Cache and Know Your Constellation; and Controllable Hover Pack's build wrapper. Each resource must equal its standalone build byte for byte. `tests/test_components.py` runs each component's suites in its folder, one after another per component, and skips the interactive desktop capture unless `--desktop-capture` is given.

v35 adds the Better Lobby Management v1.0 option. Its standalone entry is assembled from its `src/` files by its own `scripts/entry.py`, which the build runs on the vendored sources; the option ships those bytes as its plaintext discovery entry (lock fields `version` and `entry: direct`), and the build requires them to match the standalone v1.0 resource byte for byte. The other sixteen components are unchanged from v34. The option-selection suites now replay 564 of the 131,072 selections (every selection of at most two options or missing at most two, and 256 seeded random ones), and the component suites run in parallel.

v34 updates Flame Damage Fixed to v1.1 (a private Havok system group per weapon instead of v1.0's collision-layer copy; the restored flame parts are not drawn). Its option still ships the standalone addon resource byte for byte (lock field `source`). The other fifteen components are unchanged from v33.

v33 adds three options: Flame Damage Fixed v1.0, Mod Options Menu v1.0.1 and Mod Bindings Menu v2.0. Each ships its standalone addon resource byte for byte, a plaintext discovery entry like Clickable Scrollbars, Arc Thrower Revamped and Ship Station Hotkeys (lock field `source`). The Mod Bindings Menu option also carries a second triplet, `9ba626afa44a3aa3.patch_1`, with its `content/input` config override: the build recreates it with Mod Bindings Menu's own pinned `scripts/build.py` from the builder's unmodified `content/input.config` (`HD2_INPUT_CONFIG`, checksum-checked) and requires it to match the standalone v2.0 archive byte for byte (lock fields `input_config_sha256` and `input_archive_sha256`). The other thirteen components are unchanged from v32.

v32 updates Shallow Water Diving to v3.8 (optional Mod Options Menu depth slider; one protection query per write; allocation-free checks with a one-read idle gate; one protection query per water-record table). The other bundled components are unchanged from v31.

v31 raises the game's shared LuaJIT code cache limits (`maxmcode=65536` since v37, `maxmcode=16384` in v31-v36; `maxtrace=8000`) once at startup when `CowboyBingusModLoader.jit` is absent or not managed, that is with a loader older than v18; loader v18 manages the cache itself and the pack leaves it alone. No per-frame work; the bundled components are unchanged from v30.

v18 updates Clickable Scrollbars to v2.7 and Arc Thrower Revamped to v1.2. Scrollbar input uses native menu geometry without screen capture or wheel injection. Arc Thrower discovery checks active fire commands first, spreads the startup scan across updates, and runs once per update. Routine input logging is disabled in both. In-game verification of these changes is pending.

v17 updates Arc Thrower Revamped to v1.1, fixing native binding declarations and function detection. The startup regression suite uses real Windows LuaJIT FFI, preserves callbacks, and rejects an unsupported synthetic image without writes. v16 updates the bundled Clickable Scrollbars to v2.6 and requires Loader v15 / API 1. v13 added it to the pack. v12 updated the bundled Armory Preview Cache to v18. v11 added [declared entry discovery](DISCOVERY_MIGRATION.md). Pinned gameplay bytecode is embedded unchanged inside plaintext entries; entry-envelope hashes change.

One stable manager GUID (`876060ae-0640-4ac5-95b6-ec7c9a0567d3`; the discontinued Rows package used `fb497df5-080b-48a5-b31d-103ccb060e1c`) exposes twenty-one top-level Version 1 manifest options. Each option includes only `options/<component slug>`, containing its own `9ba626afa44a3aa3.patch_0` triplet; the Mod Bindings Menu option also holds the `patch_1` triplet with its input actions. Both Arsenal and HD2MM renumber selected archives through their normal deployment backends. There are no root-level patch files or all-in-one fallback, so an empty selection deploys no pack resources.

Each option's `patch_0` archive contains exactly its declared entry (Hellpod Drop Hold's also its compiled implementation) and an identical copy of `mods/cowboybingus/vanilla_plus_megapack`. The identity resolves once by resource ID even when several options are enabled, preserving pack diagnostics for any nonempty selection without an extra user-facing core checkbox. Its `modules` list is the available inventory; consult the loader's module statuses for what actually loaded. Embedded gameplay bytes must match the original standalone release hashes.

Unchecked options do not deploy their gameplay resources. The loader's existing optional registry skips absent resources. A separately enabled standalone or other pack can still provide an unchecked resource; disable that copy to turn the feature off. No runtime configuration or loader change is required.

Loader v13 registers the megapack identity before the existing gameplay entries. The identity publishes the name, revision and component inventory to `CowboyBingusModLoader.megapack`. It does not install another update wrapper or recursively start components. The shared coordinator continues to check and require each gameplay resource exactly once, in the existing order, with lookup/load failure isolation. A failed identity does not prevent gameplay entries or the optional overlay from being attempted.

The pack deliberately does not own `boot` or `core/wwise/lua/wwise_flow_callbacks`. The latter belongs to the separately installed loader. Earlier loader registries may start familiar gameplay entries, but the v13 pack identity rejects their version. Only Loader v15 or newer is supported for this package.

The standalone packages overlap the pack at their corresponding resource IDs. Identical revisions retain identical implementation bytes inside different entry envelopes. Each resource resolves once, and each gameplay entry point claims a global state before installing callbacks. Re-entering an entry point preserves that state and does not wrap callbacks again. Mixed revisions follow manager priority. give the pack winning priority to select its bundled versions. Legacy packages that replace startup scripts still require the loader migration described in the loader instructions. Selection happens before launch through the manager's Include folders.

Source and compiled-resource hash checks, upstream synthetic tests, strict archive/manager checks and compiled startup integration provide offline evidence. They do not establish live frame timing, native gameplay correctness, or multiplayer compatibility. Supported build fingerprints remain those embedded by each component: Steam 25480438 / EXE 1.8.46015.0.

## Manager verification

The contract follows [Arsenal's Version 1 schema](https://docs.rsnl.gg/mod-builder/manifest) and [checkbox semantics](https://docs.rsnl.gg/mod-management/actions#mod-options), and HD2MM's [V1 deployment implementation](https://github.com/teutinsa/Helldivers2ModManager/blob/master/Helldivers2ModManager/Services/ModService.cs). Neither manifest forces selection defaults; review options after upgrades.

The package and compiled-loader tests cover 720 of the 2097152 selections: none, all twenty-one, every selection of at most two options or missing at most two, and 256 seeded random ones. Optional backend harnesses import a release ZIP into isolated Arsenal 0.36.0 and HD2MM fixtures, deploy every selection, compare every deployed archive byte for byte (the Mod Bindings Menu option deploys two), and verify purge, re-enable and removal; they have not yet run on v33. No live game directory or manager profile is used. See CONTRIBUTING.md for commands.
