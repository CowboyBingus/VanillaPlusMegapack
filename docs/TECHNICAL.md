# Bundle contract

v42 includes the refreshed Mod Bindings Menu v2.2.1 pre-release. Its MODS tab borrows only game text IDs that all 15 of the game's language string sets have (six were removed from its label pool). It also removes inherited developer mappings from registered actions' native reset defaults, so a per-device Revert cannot restore hidden mouse or controller inputs. Original defaults are retained privately for recognizing older saved lists; existing custom live bindings are preserved. It is still a plaintext entry assembled by its `scripts/entry.py` (lock field `entry: direct`) with the bundled suites run in LuaJIT and in the game's `lua51.dll`; its input action identities and packaged input resource are unchanged. Ordinary gameplay idle checks and binding polling are unchanged. Native reset defaults are checked each binding-page frame and during periodic binding sweeps; live validation and measurement of the added work are pending. The other twenty components are unchanged from v41.

v42 also updates Match Your Colors to v1.5 (refreshing the pre-release): the Recolor Squadmates option, Match Materials carried onto hard paint, cape sources matched as they look, no armor left in one color, cape designs kept readable by lightness, cape-design sheets pooled by layout, modded gear without a color table read and recolored through its albedo texture, the Recolor Weapons option (weapons repainted as a paint scheme of their own in the outfit's colors, a picked weapon scheme as the game paints it), an extensible sync value (`cbmyc2`, beside the v1.3-v1.4 `cbmyc`), the loadout screen's squad cards in each player's colors, the Squadmates' Colors choice (squadmates in their own gear's or your colors) and the Hide Cape choice (your cape, or every Helldiver's, hidden on the ship and in missions). It adds eleven source files (`src/albedo.lua`, `src/bindings.lua`, `src/cloak.lua`, `src/lineup.lua`, `src/loadout.lua`, `src/options.lua`, `src/sheets.lua`, `src/variety.lua`, `src/weapon_data.lua`, `src/weapons.lua`, `src/zones.lua`) and the `tests/test_weapons.lua` suite and is still a plaintext entry from its own `scripts/build.py` `assemble()` (lock field `entry: direct`) with the same bundled suites, run in LuaJIT and in the game's `lua51.dll`.

v42 also adds Stratagem Hero Expanded v1.0 (refreshing the pre-release), the twenty-second option: the ship's Stratagem Hero arcade draws from all 96 loadout stratagems and 12 common mission stratagems (108) instead of 27. Like Sticky Grenade Handles it is a plaintext entry from its own `scripts/build.py` `assemble()` (lock field `entry: direct`); its bundled suites run in LuaJIT and in the game's `lua51.dll`. The other twenty-one components are unchanged. The option-selection suites replay 764 of the 4,194,304 selections.

v42 also adds Sound Systems Rebalanced v1.0, the twenty-third option. Mission music plays at the war-table volume in every mission, also when you join one in progress, and no longer goes silent on the seven planet types its biome tracks had no version for. Its option carries two archives, like Mod Bindings Menu's: a plaintext entry from its own `scripts/build.py` `assemble()` (lock field `entry: direct`; one 4-byte memory read every 0.25 s of game time and one Wwise state set at each mission start), and a patched `music_init` sound bank, built by its own `scripts/biome_patch.py` from the builder's unmodified vanilla music banks (`HD2_MUSIC_BANKS`, pinned as `music_banks_sha256`) and pinned as `music_archive_sha256`. The bank change runs no code. Its bundled suites run in LuaJIT and in the game's `lua51.dll`, and its bank tests against the vanilla banks. The other twenty-two components are unchanged. The option-selection suites replay 810 of the 8,388,608 selections.

Pinned gameplay bytecode is embedded unchanged inside plaintext entries; entry-envelope hashes change.

One stable manager GUID (`876060ae-0640-4ac5-95b6-ec7c9a0567d3`; the discontinued Rows package used `fb497df5-080b-48a5-b31d-103ccb060e1c`) exposes twenty-three top-level Version 1 manifest options. Each option includes only `options/<component slug>`, containing its own `9ba626afa44a3aa3.patch_0` triplet; the Mod Bindings Menu option also holds the `patch_1` triplet with its input actions. Both Arsenal and HD2MM renumber selected archives through their normal deployment backends. There are no root-level patch files or all-in-one fallback, so an empty selection deploys no pack resources.

Each option's `patch_0` archive contains exactly its declared entry (Hellpod Drop Hold's also its compiled implementation) and an identical copy of `mods/cowboybingus/vanilla_plus_megapack`. The identity resolves once by resource ID even when several options are enabled, preserving pack diagnostics for any nonempty selection without an extra user-facing core checkbox. Its `modules` list is the available inventory; consult the loader's module statuses for what actually loaded. Embedded gameplay bytes must match the original standalone release hashes.

Unchecked options do not deploy their gameplay resources. The loader's existing optional registry skips absent resources. A separately enabled standalone or other pack can still provide an unchecked resource; disable that copy to turn the feature off. No runtime configuration or loader change is required.

Loader v13 registers the megapack identity before the existing gameplay entries. The identity publishes the name, revision and component inventory to `CowboyBingusModLoader.megapack`. It does not install another update wrapper or recursively start components. The shared coordinator continues to check and require each gameplay resource exactly once, in the existing order, with lookup/load failure isolation. A failed identity does not prevent gameplay entries or the optional overlay from being attempted.

The pack deliberately does not own `boot` or `core/wwise/lua/wwise_flow_callbacks`. The latter belongs to the separately installed loader. Earlier loader registries may start familiar gameplay entries, but the v13 pack identity rejects their version. Only Loader v15 or newer is supported for this package.

The standalone packages overlap the pack at their corresponding resource IDs. Identical revisions retain identical implementation bytes inside different entry envelopes. Each resource resolves once, and each gameplay entry point claims a global state before installing callbacks. Re-entering an entry point preserves that state and does not wrap callbacks again. Mixed revisions follow manager priority. give the pack winning priority to select its bundled versions. Legacy packages that replace startup scripts still require the loader migration described in the loader instructions. Selection happens before launch through the manager's Include folders.

Source and compiled-resource hash checks, upstream synthetic tests, strict archive/manager checks and compiled startup integration provide offline evidence. They do not establish live frame timing, native gameplay correctness, or multiplayer compatibility. Supported build fingerprints remain those embedded by each component: Steam 25480438 / EXE 1.8.46015.0.

## Manager verification

The contract follows [Arsenal's Version 1 schema](https://docs.rsnl.gg/mod-builder/manifest) and [checkbox semantics](https://docs.rsnl.gg/mod-management/actions#mod-options), and HD2MM's [V1 deployment implementation](https://github.com/teutinsa/Helldivers2ModManager/blob/master/Helldivers2ModManager/Services/ModService.cs). Neither manifest forces selection defaults; review options after upgrades.

The package and compiled-loader tests cover 810 of the 8388608 selections: none, all twenty-three, every selection of at most two options or missing at most two, and 256 seeded random ones. Optional backend harnesses import a release ZIP into isolated Arsenal 0.36.0 and HD2MM fixtures, deploy every selection, compare every deployed archive byte for byte (the Mod Bindings Menu option deploys two), and verify purge, re-enable and removal; they have not yet run on v33. No live game directory or manager profile is used. See CONTRIBUTING.md for commands.
